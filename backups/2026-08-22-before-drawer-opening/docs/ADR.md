# Architecture Decision Records

## 철학
전생서랍은 콘텐츠형 MVP다. 초기에는 과도한 기능보다 동일 입력의 재현성, 모바일 전환 흐름, 결제 전 운영 리스크 방어를 우선한다.

---

### ADR-001: Next.js App Router 선택
**결정**: Next.js App Router와 TypeScript strict mode를 사용한다.  
**이유**: 랜딩, 테스트, 결과, API route를 한 프로젝트에서 빠르게 구현할 수 있고 Vercel 배포와 잘 맞는다.  
**트레이드오프**: 서버/클라이언트 경계를 잘못 나누면 비밀 키 노출 위험이 있으므로 API boundary 규칙을 강하게 둔다.

### ADR-002: Soul Engine은 LLM과 분리
**결정**: 핵심 전생 설정은 deterministic Soul Engine이 만들고, LLM은 문장 작성에만 사용한다.  
**이유**: 같은 입력이 같은 결과를 반환해야 신뢰와 캐싱이 가능하다.  
**트레이드오프**: 완전 자유 생성보다 결과 다양성은 줄지만 운영 안정성이 높아진다.

### ADR-003: Phase 1은 메모리 저장소, Phase 2는 Supabase
**결정**: MVP 골격은 repository 인터페이스와 메모리 구현으로 시작한다.  
**이유**: 도메인과 UI를 먼저 검증하고 DB 의존성을 나중에 붙일 수 있다.  
**트레이드오프**: 개발 서버 재시작 시 데이터가 사라진다. 실제 운영 전 Supabase 구현은 필수다.

### ADR-004: 무료 테스트는 비로그인, 결제 전 로그인
**결정**: 무료 결과까지는 익명 세션으로 허용하고, 결제와 unlock부터 로그인 필수로 전환한다.  
**이유**: 광고 유입 전환율을 지키면서 결제 후 복구와 환불 대응을 가능하게 한다.  
**트레이드오프**: 익명 결과를 계정에 연결하는 claim flow가 Phase 2에 필요하다.
